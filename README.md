# 深空回绕时标因果审计服务 (wrap-audit)

地面站汇集多个设备的回绕时标（模 `M` 计数器读数）。本服务判定一组带因果窗口的
记录能否落在同一条真实时间线上，并给出可复算的证据。**相同的计数值不会被视作
同一时刻**——每个事件的绝对 tick 为

```
t_e = counter_e + M * k_e ,   k_e ∈ ℤ, k_e ≥ 0   (回绕次数，计数器自纪元 0 起)
```

锚点事件的绝对 tick 已知（无回绕变量）。约束 `src → dst = [lo, hi]` 表示闭区间
`lo ≤ t_dst − t_src ≤ hi`。全部事件必须经约束（无向）连通锚点，否则请求被 400
拒绝。回绕次数以整数精确展开（全程整数运算，无浮点）。

## 判定结论

| status     | 含义 | 证据 |
|------------|------|------|
| `unique`   | 唯一时间线 | 每事件回绕次数 + 从锚点出发的推导链 |
| `multiple` | 多解 | 前两条规范时间线（按事件标识字典序最小的回绕向量）+ 首个不稳定先后关系 |
| `unsat`    | 无解 | 可复算的冲突约束链（下界推导 vs 上界推导，含 k 空间与 tick 空间数值） |

示例：`M=100, 锚点 A=95, B=3, A→B=[8,8]` ⇒ `unique`，`B` 唯一展开为 **103**
（`k_B = 1`）。

首个不稳定先后关系：按事件标识顺序（锚点最前）找到的第一对 `(a, b)`，其在所有
解中 `t_a − t_b` 的精确范围跨零（先后关系随解翻转）；证据含两条规范时间线中的
实际差值。无解链示例：`A→B=[8,8]`（`t_B=103`）与 `B→A=[92,92]`（`t_B=3`）⇒
`k_B ≥ 1` 与 `k_B ≤ 0` 冲突，证据给出两条推导链及每步所用的约束。

## API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET  | `/health` | 健康检查，`{"status":"ok"}` |
| POST | `/audits` | 创建审计：`201` 新建 / `200` 幂等重放 / `400` 载荷非法 / `409` 同标识不同载荷 |
| GET  | `/audits/{no}` | 按编号读取冻结的输入、结论与证据 |
| POST | `/audits/{no}/repairs` | 对冻结的 **无解** 审计发起最小窗口放宽修复（修复标识 `fix_id`） |
| GET  | `/repairs/{no}` | 按修复编号读取冻结来源、最小代价与修复证据 |

### 最小窗口放宽修复

审计员先 GET 读取到一条 `unsat` 审计，随后可携带修复标识对其发起修复。
修复**只**允许把因果窗口向外放宽整数 tick，记录本身（模数、计数器读数、
锚点、回绕次数 `k_e ≥ 0`）一律不改：

```
constraint src → dst = [lo, hi]
    lo' = lo − x ,   hi' = hi + y ,   x, y ≥ 0 且为整数
最小化  Σ(x + y)
```

服务冻结无解记录的输入与冲突证据，**来源审计及其读取结果永不改写**。
引擎在事件计数模数与非负回绕次数约束下精确最小化所有窗口扩展量之和
（全程整数运算）。同扩展量的方案依次按：

1. 约束标识序列上的放宽向量 `(x₁,y₁,x₂,y₂,…)` 字典序；
2. 事件标识序列上的回绕向量（规范时间线）字典序

裁决。修复结果含规范时间线、逐约束的**原窗口 / 放宽方向 / 放宽后窗口 /
复算差值**、最小总扩展量，以及可复算的最优性证据（整数最小费用环流代价与
加权原始值强对偶一致，并用冻结求解器对放宽后实例复算可行性）。

```bash
curl -X POST localhost:8080/audits/42/repairs \
  -d '{"fix_id":"fix-001"}'
```

* 仅 `unsat` 来源可修复：来源不存在 ⇒ `404`；来源为 `unique`/`multiple`
  ⇒ `409`；`fix_id` 缺失 ⇒ `400`。
* 请求体可省略 `payload`（始终以冻结的来源输入为准）；若携带 `payload`，
  必须与冻结来源输入逐字节一致，否则 `409` 拒绝且不产生任何新结果
  （无法引用无解记录或复用修复标识却改变载荷时不得创建新结果）。
* **幂等**：相同 `fix_id` + 相同冻结载荷重传返回原修复编号
  （`200, replayed=true`）。修复记录与来源引用一并持久化于 SQLite，
  服务重启后按编号仍可核对冻结来源、最小代价与修复证据。

POST 载荷：

```json
{
  "request_id": "req-001",
  "modulus": 100,
  "anchor": {"id": "A", "tick": 95},
  "events": [{"id": "B", "counter": 3}],
  "constraints": [{"id": "ab", "src": "anchor", "dst": "B", "window": [8, 8]}]
}
```

* 事件至多 12 个；`counter ∈ [0, M)`；约束窗口为整数闭区间 `[lo, hi]`；
  端点为事件标识或 `"anchor"`。
* **幂等**：相同 `request_id` + 相同载荷（规范化 JSON 的 SHA-256 一致）重传
  返回原审计编号（`200, replayed=true`）；任一事件或约束改动 ⇒ `409` 拒绝且
  不新增记录。记录持久化于 SQLite（`AUDIT_DB`，默认 `/data/audits.db`）。

## 求解方法（整数差分约束）

约束代入 `t_e = c_e + M·k_e` 后化为 `k` 空间的整数差分约束（边界除以 `M` 时
精确 ceil/floor 取整），外加合成纪元节点 `Z=0` 上的 `k_e ≥ 0`：

```
anchor→e [lo,hi] :  ceil((lo+A−c_e)/M) ≤ k_e ≤ floor((hi+A−c_e)/M)
e→anchor [lo,hi] :  ceil((lo+c_e−A)/M) ≤ −k_e ≤ floor((hi+c_e−A)/M)
s→d      [lo,hi] :  ceil((lo+c_s−c_d)/M) ≤ k_d−k_s ≤ floor((hi+c_s−c_d)/M)
```

下/上界同步松弛（最长/最短路传播）至不动点：出现 `low > high` 或正权环即无解，
并沿前驱链输出可复算证据。所有变量界有限 ⇒ 解集有限：全变量 `low == high` 即
唯一；否则用前缀固定 + 重传播取字典序最小/次小可行向量（固定前缀下每变量可行
值是连续整数区间），成对 tick 差的精确范围由可行性二分搜索求得。

## 修复求解方法（整数最小费用环流）

固定回绕向量 `k` 时，每条约束的最小放宽被强制为
`x = max(0, lo − (t_dst − t_src))`、`y = max(0, (t_dst − t_src) − hi)`，故
原问题为 `min_{k_e ≥ 0} Σ hinge`。离散凸（hinge）函数的凸共轭是事件图上的
有向费用弧：以锚点为接地节点 `G=0`，弧 `e → G` 容量无限、费用 0 编码
`k_e ≥ 0`。每条约束（端点残差 `r_u, r_v`，`a = lo + r_u − r_v`，
`b = hi + r_u − r_v`）给出两段常数边际费用弧：

```
L = ceil(a/M), d = a − M(L−1) ∈ [1,M] ;  U = floor(b/M), e = b − MU ∈ [0,M−1]
下界放宽弧  v → u : (M−d) 单位费用 −(L−1)，d 单位费用 −L
上界放宽弧  u → v : (M−e) 单位费用 U，    e 单位费用 U+1
```

最小化加权共轭即整数**最小费用环流**（负环抵消至残量无负环）。两级字典序
裁决用一组超递增（混合进制，基数为 `k=0` 处总代价 + 1）权重把
`(总扩展量, 放宽向量…)` 编码进一个加权原始目标：最优环流费用是一个混合进制
数，逐位整除即解出总扩展量与各 `(x_i, y_i)`；再以冻结求解器对放宽后实例
复算，取字典序最小可行回绕向量作为规范时间线。费用与加权原始值的强对偶校验、
放宽后可行性复算一并写入修复证据。全部为大整数精确运算。
